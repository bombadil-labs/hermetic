An ESLint plugin for TypeScript and JavaScript

Hermetic functions

A hermetic function reads nothing but its inputs: its arguments, including this, and a short list of allowed globals such as Math and JSON. It doesn't use imports, module-level variables, or globals like fetch and Date. Anything else it needs has to be passed in, so all of its dependencies are visible in its inputs.

Inputs, including this

Every value a function reads is one of its inputs, whether or not it appears in the parameter list. A function that reads a module-level variable or calls fetch has inputs its signature doesn't show. The hermetic/sealed rule reports every such input in a hermetic function: an import, a module-level variable, a global like fetch, or Math.random.

this is an input like the others: an implicit first argument. .call passes it explicitly, and .bind fixes it in advance, which is partial application. That makes this a convenient place for dependencies: bind them once, and pass the other arguments at each call. TypeScript type-checks the value of this in every .call, .apply and .bind.

The essay Thinking Like a Function explains this way of looking at functions in more depth.

Hermetic doesn't mean pure. A hermetic function can still change its inputs, or call methods on them that do I/O. Purity can't be checked in JavaScript, because any input can be a Proxy. Whether a function reads anything besides its inputs can be checked, with the same scope analysis ESLint uses to find undefined variables.

It isn't a sandbox either. Every value, even a literal, leads through its prototype chain to built-ins the whole program shares, and a hermetic function can still change them: ({}).__proto__.hasOwnProperty = () => true changes hasOwnProperty for every object. The rule checks names, not where values lead. To confine code you don't trust, use Hardened JS: it freezes the shared built-ins, and gives code its own global object holding only the globals you choose. 

function applyDiscount(this: Pricing, invoice: Invoice) {
  "use hermetic";
  const discounted = invoice.total * (1 - this.rate);
  return { ...invoice, total: this.clamp(discounted) };
}

// Supply the dependencies once, by binding this.
const pricing = { rate: config.rate, clamp: toCents };
export const applyPricing = applyDiscount.bind(pricing);

What you get

Portable code

The function's source is all of its behavior, so it runs the same in another file, a worker or a sandbox: new Function("return " + fn.toString())() behaves exactly like fn.

Tests without module mocks

Pass test values as inputs instead of mocking modules. Wrap this in a Proxy to record every use of the dependencies the function was given.

Dependencies you can find

To find out which functions can call Stripe, look at the code that passes the Stripe client in.

Self-contained changes

A function's inputs, the type of this and its body are everything a person or an agent needs to read before changing it.

Make existing code hermetic

hermetic/prefer-hermetic finds functions that are already hermetic and marks them. With the lift option, it also rewrites functions that read module-level values. The body moves into a new hermetic function that receives those values through this, and the original function becomes a wrapper that passes them in. Its name, signature and export stay the same, so callers don't change.

Removing the cost at build time

A lifted function makes one extra call and a few property reads each time it runs. unlift reverses the rewrite exactly, turning each wrapper back into the original function, so the source can stay hermetic while the build runs the original code.

In the table, the unlifted source performs like the second copy of the original, so the remaining difference is noise. Unlifting the lifted code gives back the original program in every file, and Effect's {{effect.suite.unlifted.passed}} tests pass on the unlifted source too. unlift isn't part of the published package yet; a bundler plugin that runs it on production builds is next.

Get started

Install the plugin next to typescript-eslint and add the recommended config. Mark a function with a "use hermetic" directive or an @hermetic JSDoc tag. The rule only checks marked functions, so turning it on doesn't affect the rest of your code.

Documentation: hermetic/sealed, hermetic/prefer-hermetic, and choosing the allowed globals. 

// eslint.config.js
import { defineConfig } from "eslint/config";
import tseslint from "typescript-eslint";
import hermetic from "@bombadil/hermetic";

export default defineConfig(
  ...tseslint.configs.recommended,
  hermetic.configs.recommended,
);
